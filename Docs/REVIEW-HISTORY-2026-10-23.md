## First implementation batch

C3/C4 code and deterministic tests implemented. The endpoint caches a coherent clock and a stable timestamp per period/epoch. Each serialized audio reader has its own cached clock; a failed snapshot does not mute fresh data. Inactive and clocks older than 100 ms still mute. A master-clock prediction discrepancy larger than max(2 frames, callback frames / 4) increments the epoch, mutes and invalidates the engine for a fresh session. This tolerance requires hardware qualification; it is not proof that every smaller discontinuity can be detected.

Shared-memory Magic changed: broker, driver and service must be built and installed together. The first clock/telemetry batch was signed and installed on 2026-10-23. Broker and driver were replaced together and Core Audio restarted. The second batch below was also built, installed and tested on the physical setup.

Optional STUDIOPATCH_TIMING=1 in the service enables per-device capture publication records and playback publication records. Atomic payload plus slot sequences prevent torn snapshots. Margin checks cover every constituent block, including interior holes. Unmatched records are telemetry misses, not audio-dropout counts; sample tags remain authoritative. SPStatus exports minimum signed host ticks, sample counts, histograms, unmatched counts and coherent latest service/ReadInput/WriteMix cycle observations. Histogram buckets have upper bounds 1,2,4,...16384 frames, followed by overflow; bucket zero also includes nonpositive margins. Minimum INT64_MAX means no observation. Latest cycle observations are independent snapshots, not paired phase distributions.

The libASPL hook passes actual AudioServerPlugInIOCycleInfo to the handler. Its old zeroTimestamp argument is not used as a callback boundary. Shared sample boundaries remain a hypothesis.

Tools/latency-capture.cpp supports STUDIOPATCH_TEST_LOAD=0..0.95 and STUDIOPATCH_TEST_STREAM=1. Streaming permits 6..86400 seconds, uses a bounded 256-packet SPSC queue and disk worker, and rejects overflow/disk errors. Each packet supports up to 4096 frames. Load applies to each instantiated capture including an optional observer, so load tests should run without the observer; independent directional-report tests should run at load zero. Physical validation uses the existing UFX output 3 → input 3 isolated cable, with the bounded 0.008-peak test signal.

The analyzer maps samples and timestamp tables, validates continuity in chunks and scans waveform windows. Saved final 48 kHz analysis is exactly unchanged. Eight CTest suites pass, including new stream integrity/overflow tests. SwiftUI compilation required execution outside the command sandbox because Apple's macro server launches its own sandbox.

### Corrected C1 result and analyzer sensitivity

The 1024-frame windows hid short corruption in the padding-16 / 90% cell. The analyzer now also reports 64-frame correlation (0.7 threshold, diagnostic only). At 48 kHz the failing cell has 367 low-correlation windows versus zero in every other cell. More decisively, `Tools/compare-captures.py` verifies identical deterministic output and compares the received analog waveform against the 80% reference after compensating integer RTL. The 90% / padding-16 cell differs in **4048 / 19950 windows** (threshold 0.95, minimum 0.486863). Padding 32 at the same load has **zero** differing windows (minimum 0.999952). Thus C1's load concern is supported, while its idle client-buffer-32 prediction was not reproduced in the first run. A second installed-build run did reproduce small-buffer corruption (601 short-window crossings; 15,234/19,950 windows differ from the intact first-run reference). The result is phase-dependent. Do not use the in-phase model as a universal scheduling rule.

The service's default output padding is now `max(ceil(rate/3000), actualBuffer)`, with input padding at least the same block size. At 48 kHz / engine 32 this adds 16 frames compared with the previous default and totals 64 frames / 1.333 ms of transport RTL. This intentionally sacrifices the sub-millisecond target until a separate phase-shift mode is physically qualified. Test-only padding overrides remain available for controlled A/B runs.

At 96 kHz, analog filter response itself produces three short-window threshold crossings in both disabled and enabled 30-second references. Received-waveform comparison finds zero differing windows with minimum correlation above 0.99979. The 140-second streaming run completed without discontinuous timestamps or coarse correlation failures; its first common reference interval also matches above 0.99978. Seven raw short-window crossings in the full run are not proof of seven dropouts.

- **Persistent HAL lookup failure:** `pluginID` first uses the normal bundle translation, then independently enumerates plug-in bundle IDs on failure/unpublished lookup. Stale unrelated objects are skipped, matching is exact and no IDs are cached. Injected tests cover successful translation, a stale object ahead of the correct plug-in, and rejection when only unrelated plug-ins exist. This mitigates the observed failure; it does not prove which external HAL event originally caused it.
- **Automatic recovery:** native HAL status codes now cross the bridge as structured errors. At least three bad-object failures over ten seconds trigger replacement of the service's own process image. A separate main-loop watchdog catches a control task blocked for 30 seconds, including a blocked stop. The old worker cannot resume into a new engine because its process image is replaced. A close-on-exec singleton lock is reacquired by the new image. No Core Audio/broker operation is part of recovery.
- **Restart-loop protection:** an atomically persisted timestamp permits one replacement per ten minutes across process images. A second request, corrupt budget or failure to persist the budget publishes a durable stopped reason and exits successfully; the installed launch agent uses `SuccessfulExit=false`, so it must not restart that exit. Failure to execute the replacement also stops. This is intentionally bounded recovery, not an endless retry policy.
